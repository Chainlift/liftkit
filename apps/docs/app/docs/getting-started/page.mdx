# Getting started

LiftKit is a design system for React apps built on [Base UI](https://base-ui.com) where everything is proportional to everything else. From just a single, global scale factor, LiftKit computes a perfectly-proportional scaling system for typography and spacing.

By abstracting its unique scaling system behind easy-to-use CSS variables and utility classes, LiftKit makes design techniques long considered too irrational for user interfaces possible to implement at scale with little pain involved. 

These techniques, staples for graphic designers and visual artists for centuries, involve satisfying the human eye's frequent preference for asymmetry over symmetry, entropy over order, and imbalance over balance. For the sake of simplicity, LiftKit refers to all of these thousands of tiny tricks of the trade as **optical corrections.**

It's over-the-top, unlike anything you've ever used, and almost certainly a bad idea. Pretty fun, though, if you're up for a challenge. 

## Key Differences from Other Design Systems


| Aspect           | Most design systems                                         | LiftKit                                                                     |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| Layout / Spacing | Global, base-4 pixel grid                                   | No global grid. Everything's `em` based. Layouts scale relative to content. |
| Size & Scaling   | Linear, based on a factor of 1.25                           | Exponential, based on any scale factor                                      |
| Color            | Minimal set of semantic tokens, Tailwind-ish                | Maximalist set of semantic tokens, Material 3-ish                           |
| Symmetry         | Literal symmetry. Numbers add up, but designs can look off. | Optical symmetry. Numbers don't add up, but designs look more balanced.     |
| Ease of use      | Easy to learn, hard to master                               | Hard to learn, AND hard to master!                                          |


## How does it work?

Under the hood, LiftKit's system starts with a single global scale factor. 

```css
:root {
  font-size: 1rem;
  --lk-scalefactor: 1.618;
}
```
The default value is 1.618, phi, also known as the golden ratio. I chose this value because it looks the best to me, and it's what I originally designed it with. But you can set it to whatever you like. 1.25 gives you easier computed values to work with.

### The tokens in liftkit-core.css

Everything LiftKit does is defined in one file, `liftkit-core.css`, and each layer of it is built from the layer before it.

**1. Steps.** The scale factor is turned into a handful of "steps": the whole step (the scale factor itself), the half step (its square root), the quarter step and the eighth step. Each also has a `-dec` version, which is the step minus one.

```css
:root {
  --lk-wholestep: var(--lk-scalefactor); /* 1.618 */
  --lk-halfstep: calc(round(pow(var(--lk-scalefactor), 0.5), 0.001)); /* 1.272 */
  --lk-quarterstep: round(pow(var(--lk-scalefactor), 0.25), 0.001); /* 1.128 */
  --lk-eighthstep: round(pow(var(--lk-scalefactor), 0.125), 0.001); /* 1.062 */
  --lk-halfstep-dec: calc(var(--lk-halfstep) - 1); /* 0.272 */
}
```

**2. Per-family scale factors.** Typography, spacing, length and corner radii each get their own scale factor (`--lk-scalefactor-text`, `-spacing`, `-length` and `-corner`) and their own set of steps (`--lk-halfstep-text`, `--lk-halfstep-spacing`, and so on). They all default to 1.618, so out of the box they match the global one, but you can tune any of them without touching the others.

**3. Size tokens.** Powers of a scale factor become a ladder of sizes from `5xs` to `5xl`, with `md` equal to `1em`. They're all in `em`, so they're relative to the font size of whatever element uses them. That's what makes a component scale with its text.

```css
:root {
  --lk-spacing-md: 1em;
  --lk-spacing-sm: calc(1em * round(pow(var(--lk-scalefactor-spacing), -1), 0.001)); /* 0.618em */
  --lk-spacing-lg: calc(1em * var(--lk-scalefactor-spacing)); /* 1.618em */
}
```

There's one ladder per family: `--lk-spacing-*` for gaps, padding and margins, `--lk-length-*` for widths and other fixed dimensions, and `--lk-corner-*` for border radii. The general-purpose `--lk-base-*` ladder is built from the global scale factor.

**4. Typography.** Font sizes, line heights and optical offsets for each font class (`display1` down to `capline`) are built from the text steps. `--lk-title2-font-size`, for example, is one whole step above body text, and `--lk-body-line-height` is a whole step.

Changing `--lk-scalefactor` at the top therefore changes everything underneath it.

### Component classes and utility classes

LiftKit gives you two ways to style things, and they're meant to be mixed.

**Component classes** come with the components. Each component imports its own stylesheet from `css/components/`, and that stylesheet targets attributes such as `data-lk-component` and `data-slot`, plus a few modifier classes such as `lk-btn-variant--fill` and `lk-colorgroup--primary`. You normally never write these yourself. You pass props, and the component adds the right classes.

```tsx
<Button variant="outline" color="secondary" fontClass="label">
  Save
</Button>
```

Component styles are written with `:where()`, which gives them zero specificity, so any utility class you add will win without needing `!important`.

**Utility classes** are small, single-purpose classes imported globally from `css/utilities/`. Their names follow the token ladder: `p-sm`, `mt-lg`, `gap-md`, `w-3xl`, `rounded-xs`, `bg-surfacecontainer`, `color-onsurfacevariant`, and the type classes `body`, `title2-bold` and so on.

```tsx
<div className="flex items-center gap-md p-lg bg-surfacecontainer rounded-sm">
  <h2 className="title2-bold mb-xs">Wildwood Adventure Park</h2>
</div>
```

Spacing and size utilities are `em`-based, so they resolve against the element they're on. The type classes also redefine the spacing ladder to be proportional to their own line height. A `p-sm` inside a `.title2` is relative to that title, not to the page.

### Using the color system

LiftKit's colors follow [Material Design 3's color roles](https://m3.material.io/styles/color/roles). Most roles have an `on` partner for the content that sits on top of it, which keeps text and icons readable. A few, like `outline` and `shadow`, stand alone.

| Role                                            | Pairs with                                           |
| ----------------------------------------------- | ---------------------------------------------------- |
| `primary`, `secondary`, `tertiary`              | `onprimary`, `onsecondary`, `ontertiary`             |
| `primarycontainer`, `secondarycontainer`, etc.  | `onprimarycontainer`, `onsecondarycontainer`, etc.   |
| `error`, `success`, `warning`, `info`           | `onerror`, `onsuccess`, `onwarning`, `oninfo`        |
| `surface`, `surfacecontainer*`, `surfacevariant` | `onsurface`, `onsurfacevariant`                      |
| `background`, `inversesurface`                  | `onbackground`, `inverseonsurface`                   |

<Card color="secondarycontainer" scaleFactor="body" opticalCorrection="top" className="mb-md">
  <p className="body-bold mb-xs">Two tokens aren&apos;t from Material Design</p>
  <p className="subheading mb-sm">LiftKit adds two tokens that Material Design 3 doesn&apos;t have: <code>onsurfacelow</code> and <code>onsurfacelowest</code>. They&apos;re text colors for content that should read as less important than <code>onsurface</code>, such as secondary and tertiary text, and each step down has a little less contrast against the surface.</p>
  <p className="subheading">That&apos;s also what &quot;low&quot; and &quot;high&quot; mean in the surface roles. They describe contrast against the <code>surface</code> tone, not elevation. <code>surfacecontainerlowest</code> has the least contrast against <code>surface</code>, and each step up through <code>low</code>, <code>surfacecontainer</code>, <code>high</code> and <code>highest</code> has more.</p>
</Card>

Light and dark values are stored separately (`--lk-light-primary`, `--lk-dark-primary`). The tokens you use, `--lk-primary`, `--lk-onprimary` and so on, switch between them automatically based on the user's `prefers-color-scheme`, so you never write dark mode styles yourself.

```css
.my-banner {
  background: var(--lk-primarycontainer);
  color: var(--lk-onprimarycontainer);
}
```

You can also use the utility classes. `bg-*` sets the background and the matching `on` color for the text, and `color-*` and `border-color-*` set text and border color on their own.

```tsx
<div className="bg-primarycontainer p-md rounded-sm">
  <p className="body">Text is already onprimarycontainer.</p>
  <p className="caption color-onsurfacevariant">This line overrides it.</p>
</div>
```

Components take a `color` prop with the same role names. Behind it, a `lk-colorgroup--{role}` class sets two variables, `--lk-color-token` and `--lk-color-ontoken`, which the component's styles read from.

To generate a full palette from your own brand color, use the [Theme Generator](/playground). It derives every role from a seed color, lets you adjust individual tones, and exports the result as CSS.
